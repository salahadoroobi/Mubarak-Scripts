# Mubarak Scripts — V0.0.2 Development Plan

Developer: صلاح الدين الدروبي
Status: In development; not approved for mobile release.

## Repository policy
- Public `main`: published releases only.
- `archive/v0.0.1`: snapshot of the previous release.
- `develop/v0.0.2`: staging branch; avoid placing additional source secrets here.
- Private source repository: **NOT YET CONNECTED/VERIFIED**. Do not publish new sensitive source until available.

## Code review findings
1. `Mubarak.lua` uses Lua bitwise `~` which may not parse in the GameGuardian Lua runtime; replace with a compatible XOR implementation and test on device.
2. Authorization uses public `users.txt` and Linux boot ID; boot ID changes and public lists are not a secure licensing mechanism.
3. `script_source.lua` is a large monolith (~4,699 lines); migrate by feature with regression checks.
4. Settings and persistence exist in isolated functions; avoid overwriting existing data paths.
5. README incorrectly says encrypted payload is absent.
6. Hex/XOR is obfuscation, not encryption suitable for protecting secrets.

## Implementation sequence
1. Freeze baseline and document known behaviors.
2. Compatibility fixes and error handling for loader.
3. Add a bilingual UI shell without changing game-memory logic.
4. Add validated settings, backup/restore, and diagnostics.
5. Add version manifest, checksum verification, user-approved updates, rollback.
6. Add signed license verification with a server-side source of truth.
7. Split modules incrementally and run device regression tests.

## Release gates
- Lua syntax/runtime compatibility verified on device.
- Existing menus and game-memory functions regression-tested.
- License behavior, translations, persistence, restore, and updates tested.
- No source secrets or user identifiers published in release artifacts.
- Only after passing checks: promote V0.0.2 to public `main`.
